# 本轮验收结论

已完成“未知输入 → 发现 runs → 动态建树 → 执行 → 正确性及结构成本证书 → 公平实测”的闭环。分支 `experiment/dynamic-runs`，未 commit、未 push。此前未提交的算法、证明、决策树负结果和固定方案实验保留。

## 已证明

对任意有限 `List α`（合法 `LinearOrder α`），不需要给出分段答案：

- 扫描产生连续、有序、非空的 runs，拼接恰好等于输入；空列表产生零个 runs。扫描、建树、执行均为 Lean 接受的总函数。
- 两种动态建树策略的最终结果有序且保持排列；程序输出、操作语义和比较计数相互对应。
- 设输入长度为 n，实际发现的 run 数为 r，按 run 数平衡的总比较数满足：

  **C(x) ≤ max(0,n−1) + n⌈log₂r⌉**。

  这里使用 `Nat.clog 2 r`，在 r=0 时为 0；n=r=0 的成本为 0。识别精确计入 max(0,n−1) 次，合并不重新检查已认证的 runs。
- 已推出 mathlib 意义的 `O(n(1+log(max(1,r))))`、全输入 `O(n log n)`，以及全有序输入精确 max(0,n−1) 次比较。r 没有藏进常数。
- 长度策略有“识别＋实际合并树预算”的证明，不声称已证明 Peeksort 熵界。

## 实测：更少比较没有变成总体加速

完整实验：60 个校准输入，98 个未见测试输入，3 个主要长度、3 个测试种子、10 种形态及边界例子；每策略每输入 5 次计时。校准选定 Hybrid 阈值 8，测试前冻结。以下时间是 **98 个输入各自中位数之和**，不是单个样本时间、分项时间相加或置信区间。

| 策略 | 总键值比较数 | E2E 中位数之和（ms） |
|---|---:|---:|
| Merge | 58,166 | 377.387 |
| 冻结 Hybrid-8 | 58,471 | 375.933 |
| 固定两段 | 57,030 | 366.391 |
| 固定三段 | 55,483 | 374.866 |
| 固定四段 | 54,730 | 362.416 |
| 自动 runs／按段数平衡 | 49,887 | 604.529 |
| 自动 runs／长度中点策略 | 47,797 | 579.710 |

段数平衡相对 Merge 比较数少 **14.23%**，时间高 **60.19%**；长度策略相对 Merge 比较数少 **17.83%**，时间高 **53.61%**。两者扫描均计入 11,566 次比较。没有为了跑赢而重选阈值、形态或种子。

实际 r 范围是 **0–257**，其中 58 个测试输入超过 4 个 runs；71 个输入同时存在“真实边界不在固定四段切点”和“固定切点不是真实边界”。测试不依赖预设切分对齐。固定两段的条件上界只对 14/98 个输入适用，三段和四段各为 15/98；其余只使用无条件界。

## 哪些形态好，哪些差？

- **全有序**：段数平衡的比较数 1,152，Merge 为 4,236；时间却是 24.026 / 16.175 ms。即使没有合并，当前扫描表示的实测开销也不小。
- **少量长 runs**：3,051 / 5,532 次比较，58.032 / 41.667 ms。**不等长 runs**：3,097 / 5,350 次，56.026 / 37.243 ms。比较数获益，当前后端耗时没有获益。
- **随机、重复值、大量短 runs、逆序**：段数平衡在各组的总比较数和时间都高于 Merge。严格逆序 r=n；只识别非递减 runs 的第一版需要额外扫描，未利用下降 run 的反转。
- **极不均衡 runs**：长度策略比段数平衡少比较（3,339 / 4,709），也更快（59.818 / 85.737 ms）。但两者仍慢于固定四段的 31.432 ms；段数平衡的比较数也高于固定四段（4,709 / 4,550）。这暴露了“按段数平衡”可能反复合并大 run 的弱点。
- 长度策略不是逐输入支配：相对段数平衡，56 个输入比较更少、11 个更多、31 个相同；只有 35 个输入计时中位数更低。段数平衡相对 Merge 的 54 个少比较输入中，48 个反而更慢。

以上均为本批合成输入的描述性观察，不是普遍性、显著性或最优性定理。完整形态数据（含随机边界、局部扰动、所有边界例子）见 `by-shape.csv` 和 `paired.csv`，没有删掉败例。

## 退化解释与可信边界

1. **识别开销有直接证据**：全有序输入的扫描诊断为 24.084 ms，而 E2E 为 24.026 ms，建树诊断仅 0.018 ms、merge-only 约 0.120 ms。诊断是独立重放，出现轻微倒挂正常，不能相加成 E2E。
2. **合并次序有直接证据**：极不均衡组的 merge-only 诊断从段数策略的 62.217 ms 降至长度策略的 36.224 ms；建树诊断则增加（0.127 / 0.278 ms）。另有 Lean 核内证明的小例子：run 长度 1/1/16，两策略实际总比较数 50/34、树预算 35/20。
3. **执行表示是重要待检验因素**：扫描通过逐层 `Program.bind`/闭包构造比较程序，不是高效尾递归累积器。遍历、分配、闭包及解释器开销不在比较计数内，且可能随构造结构变化。诊断提示应研究执行精化，但本轮未做控制变量替换，不能断言机器时间的具体阶或唯一原因。

所有主要策略使用同一 Lean 比较程序后端。计时包含输入读取、识别、计划构造、执行、完整输出消费；不包含离线证明、校准、JSON、正确性检查与诊断重放。这里只证明键值比较成本，**不证明完整机器时间、空间或编译器正确性**。负结果不能外推为优化实现的自然归并排序没有价值。

长度对照移植 [Peeksort 原论文 Algorithm 1](https://www.wild-inter.net/publications/munro-wild-2018.pdf) 的整数中点切分策略，提前扫描非递减 runs；并非原版惰性扫描、下降 run 处理或优化数组实现。两种独立切分公式已有限穷举核对，未形式化证明与原实现等价；不能声称超过原版 Peeksort/Powersort。
