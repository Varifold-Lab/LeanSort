# 本次实验结论（2026-09-07 UTC）

已经完成一个真实的离线闭环：**参数化方案 → 可执行 Lean 算法 → 自动组合证明 → 筛选 → 测量**。
这不是新的决策树训练，也不是固定长度排序网络。原来的决策树实验及负结果仍保留。

## 证明覆盖

- 100 个结构不同的组合，另有 5 个单算法基线，均通过 Lean 检查。
- 每个条目对任意有限 `List α`、任意合法 `LinearOrder α` 保证有序和排列不变，
  并携带执行/比较计数对应关系、无条件成本界和带明确前提的条件成本界。
- 100 个组合都有保守的二次上界；其中 66 个通过充分结构规则得到固定参数下的
  `O(n log n)`，50 个得到受检分段已有序时的固定深度 `O(n)`。
- 通用结构定理覆盖语法内的所有有限方案，不仅这 100 项。生成器只实例化已证明的规则，
  不宣称自动发现定理。结构去重也不等于语义去重。
- Insertion 使用重新证明的**比较次数**，没有混用原来的交换次数。

## 有优势的条件与没有优势的例子

下面各行均使用两个长度 128 的输入；比较数、时间为这两个输入的合计。
时间是各输入 5 次端到端测量的中位数之和。上界是**每个**输入的上界。
左右数字依次为“组合 / 对照”。键值比较包含运行时有序性检查。

| 组合与对照 | 输入形态 | 已证明上界/输入 | 实际比较数/两个输入 | 时间/两个输入（ms） |
|---|---|---:|---:|---:|
| 两块 Guard＋Merge / Merge | 两个已有序块 | 254 / 896 | 504 / 1020 | 3.408 / 4.941 |
| 三块 Guard＋Merge / Merge | 三个已有序块 | 339 / 896 | 672 / 1190 | 4.904 / 6.143 |
| 四块 Guard＋Merge / Merge | 四个已有序块 | 380 / 896 | 749 / 1141 | 4.997 / 6.162 |
| 整体 Guard＋Merge / Merge | 两个已有序块，但整体无序 | 1023 / 896 | 1148 / 1020 | 5.072 / 4.941 |
| 两块 Insertion＋Merge / Insertion | 随机 | 4160 / 8128 | 4442 / 7737 | 33.173 / 111.772 |

前三行只在块有序前提成立时使用条件上界；检查没有免费忽略。
Merge 的 896 是在相同输入域上仍然有效的**通用**上界，不是已证明紧确的受限输入最坏成本。
因此这些是较小的可用保证和有限样本上的改善，不是对 Merge 的全域成本支配证明。

第四行是明确负例：整体检查失败后安全回退，增加了 128 次检查比较，结果仍正确。
第五行虽然胜过 Insertion，却远不如同批随机输入上的 Merge（1482 次比较、7.231 ms）。
换一个较弱对照，不能据此声称组合最优。

另外两项直接由 Lean 证明：

- 长度至少 8 时，两块 Insertion 的充分上界小于整块 Insertion 的上界；
  但在 `List.range 8` 上，虽然上界是 `20 < 28`，实际操作数却是 `10 > 7`。
  `twoInsertion_not_pointwise_dominates` 明确否定了逐点支配。
- 把 MergeSort 第一层拆成两个 MergeSort 再 Merge，长度至少 2 时与原比较程序相同。
  全部 62 个实测输入也有相同比较数。这里没有新的操作数优势。

## 全部样本，而不只看成功案例

离线冻结的短名单含 18 个算法，测试 62 个互不相同的输入，得到 1116 个算法/输入对和
5580 次部署计时。每轮输出均核对，计数还与独立 Python 解释器核对。

本次完整数据汇总中，四块 Guard＋Merge 是短名单内实测时间最低的一项：
11774 次比较、44.131 ms；Merge 为 13513 次、48.985 ms；Hybrid-4 为 13315 次、48.116 ms。
这只是**这批数据、这个解释器、这次运行**的描述，不是新的部署选择规则或最优性证书。
没有据此调整短名单、阈值、数据或重新测到更好结果。

数据刻意包含与方案切分对齐的 2/3/4 个有序块，用来检验条件定理；它不是生产分布的估计。
同一生成基底产生不同形态，样本之间并非统计独立。本报告不进行显著性推断。

## 开销与可信边界

- 搜索/筛选约 3.785 ms；算法及证明源代码生成约 4.969 ms。
- 生成算法的 Lean 检查约 1.677 s，证书检查约 4.713 s；这些是本次测量，不是工期估计。
- 运行时形态检查已包含在总比较数和端到端时间中；单独的 `check_replay` 只用于诊断，
  不能再次相加，也不是准确的墙钟时间拆分。
- 实测后端为 `lean --run` 的比较程序解释器；所有对照使用同一表示。
  List 切分、分配、解释器成本不属于键值比较计数，但属于端到端时间。
  这些时间不能当作优化后的 native 排序性能。
- `lake build`、新旧相关证明、9 项新 Python 测试均通过；原决策树的 12 项测试也通过。
  逐项公理审计只出现 `propext`、`Classical.choice`、`Quot.sound`，没有 `sorryAx` 或原生计算公理。
- 数据验证复核了样本完整性、唯一键、逐轮中位数、汇总分母和比较数分项之和；
  编译输出检查确认输入读取、排序、检查和输出消费没有逃出各自计时区间。
  数据/编译输出审计是检查，不是 Lean 证明。

## 数学上下一步还缺什么

更紧的条件成本界及相应下界，才能证明有意义的成本支配；
依输入动态发现 runs、改变分段数量的递归构造，需要新的终止和成本传播定理；
若要高效部署，还需要从比较程序到直接执行器的精化证明。
本阶段没有证明空间界、机器时间界或全局最优性。
