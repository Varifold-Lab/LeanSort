# 同一算法的直接执行与精化

独立实验；不改变上一阶段的 ascending runs 规则、规划器、显式合并树、Hybrid-8 或固定四段 schema。不修改主库入口，保留所有历史实验。没有 UI、训练、下降 runs 或新策略。

## 复现

在仓库根目录、已安装当前 Lean/Lake 依赖的本机运行（仅 Python 标准库与本机 CPU）：

```sh
python3 experiments/direct-executor/run.py --smoke
python3 experiments/direct-executor/run.py
```

脚本创建唯一的 `results/<UTC>-<mode>-<id>/`，不会覆盖旧结果；先运行构建、四组 Python 测试、十一个新增 Lean 模块的隔离重新编译、32 条入口定理的公理检查及编译输出检查。失败也保留日志。运行需要允许 `ps -o rss= -p <workerPID>` 读取本地 worker 内存，禁止优化模式 `python -O`（断言是验收的一部分）。不下载依赖、不联网、不 commit/push。

## 语义与证明

`LeanSort/Algorithm/Direct/Engine.lean` 是普通递归的共享算法体，以比较操作和 Monad 参数化：

- 符号实例：`Comparison.Program`，只用于参考语义及证明。
- 直接计数实例：`TimeM Nat`，比较返回 Bool 与一次计数，不构造 Program。
- 直接无计数实例：`Id`，比较直接返回 Bool，不调用计数版本再取 `.ret`。

`Verification/Direct/Symbolic.lean` 证明共享算法体的符号实例与旧比较决策树完全相等（包括比较参数和分支）；`Morphism.lean` 证明纯值、bind、比较解释与递归算法体交换。`Refinement.lean` 由此得到扫描、merge、任意树、全部已有 `Strategy`（包含任意有限静态 Schema）输出与计数精化；`Semantics/Direct.lean` 定义无计数体的符号操作语义。

因此成本迁移不是“排序输出一样，所以比较次数一样”。`execution_iff` 唯一确定直接体输出和键比较成本；正确性、排列保持、按 run 数的有限界和渐近界、全有序输入精确 n−1、长度策略实际树预算都由旧定理迁移。规划合法性沿用已证明的旧规划器，不重检已认证 runs。

## 公平计时与消融

五种策略都测 A 旧程序解释器、B 直接计数、C 直接无计数。相同 `lean --run`、`Nat` 比较器、工具链和校验和消费。A/B 实际计数写入第二个 sink 防止计数被消除；C 对同一 sink 写常数零，日志中的 C 比较数是证明的插桩成本，不是假装观察到运行时计数。

两种动态策略额外测四种分阶段组合：双旧、只换扫描、只换合并、双直接。双旧控制外层 Program.bind 的组合开销；不要把“只换扫描 vs 完整旧程序”的全部差异都归给扫描。全部仍是端到端计时，没有把独立重放分项相加。

计时范围：clock → IO 读取输入 → 扫描/规划/执行 → 完整输出 checksum 与 sinks → clock。核对完整输出、分项重放和独立 Python 计数在计时外。每个输入先预热，再按轮换/反转顺序保留全部重复值；时间摘要为各输入中位数的和，不取最好轮，不把重复次数算成样本数。

`audit.py` 检查新生成的 C 中上述位置、Id 字典、plain 比较原语和包装入口；它不是编译器证明。泛型递归仍产生普通闭包和 Monad 分派；当前 Nat 运行入口的 C 特化进一步消除了 plain 核心中的 TimeM、动态分派和闭包分配。审计分别记录泛型与特化路径，不能把这一观察扩大为整个进程零分配或编译器证明。本轮不测原生 C 后端，避免混淆。

## 冻结与数据

`config.json` 在首次性能观察前确定：主实验五轮，旧 98 条完整输入原样用于已见配对诊断；实现冻结后才生成独立确认集（3 个新种子 × 3 长度 × 10 形态 = 90 输入）。阈值一直为上轮独立校准的 8，不重新选择。重复计时不是独立输入。冒烟使用另一个种子和边界输入，不触碰确认集计时。

完整运行保存源码哈希、工具链/环境、冻结参数、所有输入、实际发现的 run 长度、规划结构、分项比较数/成本界、所有请求与响应、每轮 ns、公理与构建日志、编译检查证据、CSV、JSON 和中文统计。`phase-wall-times.json` 单列离线构建/证明和含核对的阶段墙钟，不混成排序时间。脚本末尾核对源码与 git 引用未改变。

主实验通过后运行 1024/4096/16384 的单独扩展（random/sorted/skewed_runs，每长一固定新种子）。请求预算 5 秒、全段 180 秒、worker 栈 8 MiB；0.25 秒间隔采样 RSS，超过 3 GiB 终止，不宣称瞬时硬内存上限。保留超时、崩溃和预算未执行项；仅对各变体都完成的配对集合比较，不通过丢弃失败美化。

只证明键比较成本，不证明 List 遍历、分配、实际耗时、编译器正确性或全局最优。若仍退化，保留负结果并区分控制变量支持的差异与尚未验证的原因。

预算修订记录：两次初始 1 GiB smoke 都在 Lean 启动、任何输入计时之前失败；本机为 24 GiB。所有变体统一改为 3 GiB，再冻结并运行，不是根据排序成绩选择预算。旧失败目录完整保留。
