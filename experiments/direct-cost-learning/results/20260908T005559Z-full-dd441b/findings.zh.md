# 直接执行器上的成本学习：完成，但尚未超过简单规则

本轮真正完成了数据积累 → 两类模型训练 → 验证选型 → 冻结 → Lean 进程内推理 → 未见评测。没有更改上一轮直接执行器、扫描规则、规划器、Hybrid 阈值或排序内核。本实验是 **7 个已有、已验证候选的学习选择**，不是新算法综合。

主要结果：同分布未见测试上，分类树慢 2.65%，成本预测树慢 1.33%；更长输入上分别快 4.29%、5.63%，但仍未胜过预先冻结的简单抽样规则。不预设学习必胜，也没有依据最终结果重新训练或换参数。

## 1. 实际训练了什么

候选：Merge、Hybrid-8、固定两段／三段／四段、按 run 数平衡、原长度策略。固定分段使用原有 Schema 通用执行器与证明，不是新增未验证内核。`catalogue.json` 给出 ID、入口、适用前提、证书和成本公式。对输入形态作运行时检查的成本仍在内核内计数、计时。

训练特征为长度，以及最多 16 对分散相邻元素的下降率、相等率、跨探针下降率和采样值域，共 6 个整数。生成家族、种子、生成边界、参考输出和性能标签均未进入模型。抽样预算固定，但 List.length 和到达探针的遍历不是常数时间。没有复用 runs，因此重复扫描的开销如实计入。

- 分类器：Gini CART，学习近似最快的候选 ID；2% 以内按近似平手处理，优先训练前缀中的最佳固定候选。
- 成本模型：多输出回归 CART，预测每个候选的“耗时 / 该训练输入事后 Oracle 耗时”，输出 7 个相对成本，再取最小值。它不预测证明上界，也不把上界当实际时间。整数叶节点使 Python 与 Lean 预测一致。

仅使用 Python 标准库和本机 CPU。深度候选 2/4、叶最少样本 4/8；每规模每类 4 个模型，共 24 个快照。模型只负责性能决策，非法 ID、缺失特征、损坏或不支持的模型都经合法分派回退到 Hybrid-8。

训练规模 80、160、320，固定验证集 120；最终测试 120，长度外推 40。总计 600 个不同输入、60 个基础序列组：训练 32 组、验证 12 组、测试 12 组、外推 4 组。**同组 10 种形态相关，并非独立同分布样本**；自动统计中的“输入数”是不同序列数，不能把 120 个测试序列或重复计时说成 120 个独立随机基础样本。本报告仅作描述性比较，不作显著性声明。

覆盖随机、有序、逆序、重复、不等长 runs、随机边界、短 runs、长 runs、局部扰动、极不均衡 runs。完整输入和真实发现的 run 长度已保存。每组所有派生形态在同一划分；输入和基础序列哈希均无跨集泄漏。旧解释器和直接执行器历史耗时都没有混入标签。

训练／验证长度 24、80、240、512；外推长度 768、1536。模型于 **2026-09-08 00:57:19 UTC** 冻结，此后才生成最终输入。三个规模均使用同一验证集；最终模型预先规定从最大训练规模中按验证 E2E 选超参数，并没有回选较小规模来美化最终结果。

## 2. 更多训练数据有改善吗

| 训练输入 | 分类树：验证 E2E / 固定 | 成本树：验证 E2E / 固定 |
|---:|---:|---:|
| 80 | 1.0243 | 1.0134 |
| 160 | 1.0145 | 1.0131 |
| 320 | 1.0169 | 1.0221 |

没有单调改善，也没有在任一规模稳定超过固定候选。分类树的选中内核／Oracle 平均比值为 1.0398 → 1.0346 → 1.0326；成本树为 1.0211 → 1.0179 → 1.0220。模型确实学到选型结构，但不能据此宣称数据越多性能越好。各规模分别重测同一验证集，微小差别也可能包含计时漂移；所有超参数结果均保留。

320 个训练输入产生 2,240 个候选标签，每标签 5 个直接执行计时。训练选择的最佳固定候选是 **runs_count**：60.143 ms；免费逐输入候选 Oracle 为 53.480 ms，约有 11.08% 理想空间，并非完全没有选择机会。训练输入的最快候选确实不同，主要在 Hybrid-8 与 runs_count 之间；完整家族分解见 `opportunity-prefix-8.json`。

最后两棵树深度均为 2，各 7 个节点。分类树紧凑 JSON 808 字节、拟合 9.10 ms；成本树 1,051 字节、拟合 26.08 ms。24 次拟合合计 296.35 ms（不含采集／构建／验证）。成本树最终主要学到低下降率用 runs_count、高下降率用 Hybrid-8；分类树还对部分低下降、跨探针非下降输入选择固定两段。这是可解释的已有码选择，不是程序生成。

## 3. 最终未见测试：全部在线开销之后

时间单位 ms，为每个输入五轮中位数之和。所有部署策略在同一持久 Lean 进程、同一直接 List 后端、同一比较器下交替执行；完整输出消费在计时内，精确结果核对在计时外。特征、推理、分派、排序全部进入各策略自己的 E2E。

| 策略 | 120 输入 E2E | 相对固定 | 选中内核单独执行 | 键比较：特征＋内核 |
|---|---:|---:|---:|---:|
| 训练选定固定 runs_count | 22.622 | 1.0000 | 22.549 | 0＋125,322 |
| 预定抽样规则 | 22.808 | 1.0082 | 20.545 | 9,600＋127,404 |
| 预定长度规则 | 22.571 | 0.9978 | 22.516 | 0＋125,496 |
| 分类树 | 23.222 | 1.0265 | 21.030 | 9,600＋129,835 |
| 成本预测树 | 22.923 | 1.0133 | 20.467 | 9,600＋126,695 |
| 免费事后候选 Oracle | 非部署策略 | — | 20.030 | 0＋122,913 |

两类模型都没有超过最佳固定或人工规则。长度规则与固定候选差别只有约 0.22%，不能据此认定普遍更快。Oracle 按**实测时间**选候选，不按最少比较次数选；它没有在线提取、决策开销，不是全局最优。

不能只看总和：分类树逐输入比值中位数 1.140、P90 2.116、最大 4.061，27 胜／93 负；成本树中位数 1.164、P90 2.257、最大 4.017，24 胜／96 负。两者各有 72/120 个输入退化超过 10%。短输入的损失被较长输入在总时间中的权重部分掩盖。

按长度汇总，分类／成本树相对固定分别为：n=24 时 1.821／1.933；n=80 时 1.194／1.202；n=240 时约 1.006／1.006；n=512 时 0.983／0.957。按形态，随机、逆序、重复值有收益；长／不等长 runs、随机边界、已排序和扰动输入常有损失。分类树对局部扰动形态达到 1.403，说明稀疏探针可能让它选择不合适的固定两段方案。此处是具体实测误选，不是对所有扰动输入的定理。

## 4. 长度外推：有收益，但没赢人工规则

独立预定 40 个输入（只有 4 个基础序列组），不可与主测试混合后重新宣布整体成功。

| 策略 | E2E ms | /固定 |
|---|---:|---:|
| 固定 runs_count | 47.716 | 1.0000 |
| 抽样规则 | 44.864 | 0.9402 |
| 长度规则 | 47.784 | 1.0014 |
| 分类树 | 45.671 | 0.9571 |
| 成本预测树 | 45.029 | 0.9437 |

免费 Oracle 内核合计 42.636 ms、268,335 次比较。分类树相对抽样规则仍慢 1.80%，成本树慢 0.37%，没有证明学习模型的必要性。分类树逐输入中位比值 1.019、18 胜／22 负；成本树 1.027、15 胜／25 负。总时间改善来自若干较昂贵输入，不能解释成多数输入均变快。

## 5. 为什么没有整体收益

证据首先指向**在线开销，其次是误选；选择空间也有限**，不是已经排他性证明的唯一原因。

主测试中成本树选中内核 20.467 ms，距免费 Oracle 20.030 ms 较近，比固定内核 22.549 ms 少约 2.083 ms；实际 E2E 却为 22.923 ms。其 E2E 与选中内核独立重放的差为 2.457 ms。独立特征诊断总计 2.589 ms，约 21.58 μs/输入；分类／成本树预提取特征上的推理诊断分别约 0.85／1.92 μs/输入。分类树另有更明显的扰动输入误选。

这些诊断支持“小输入上提取成本抵消内核收益”。**不同重放不能相加冒充端到端时间，也不能用差值精确分离单一组件**；缓存状态、计时噪声等仍可能影响。长输入中近似固定的抽样算术成本更容易摊薄，和本次外推结果一致，但这仍是实验解释。

下一步优先保留固定／简单规则作为可用基线，研究更便宜、按需提取的特征及其证明接口，而非立即扩大模型或组合搜索空间。冻结的成本模型已经接近候选 Oracle，单纯增大模型缺少依据。特征变更须在新实验中重新采集标签、冻结并使用新测试集；**本轮未做这些优化**。

## 6. 哪些是 Lean 证明，哪些只是检查

已形式化证明：

- 任意候选 ID／任意选择函数经合法分派后，输出有序且保持排列；回退同样正确。候选层适用于任意有限 `List α` 和 `LinearOrder α`，本轮数值特征／模型实例为 Nat。
- 被选内核继承既有直接执行精化和比较成本界。候选目录由通用证明手工登记，不是假称自动性质发现。
- 特征的 Id／计数／Comparison.Program 解释对应，恰为每探针 5 次键比较、总计不超过 80；`selection_execution` 和 `selection_bound_80` 覆盖特征比较与所选内核的组合。并非仅凭输出相同推断比较数相同。

仅运行检查／实测：训练模型和 Lean 部署特征／叶节点／预测一致；非法模型回退；独立 Python 比较计数；每次输出与参考排序完全一致；每条适用界成立；源文件／模型冻结一致；计时范围和生成 C 的结果消费检查；上述性能、学习曲线和误选解释。

未证明：模型准确率、最优选择、墙钟性能、统计普遍性、编译器正确性。键比较计数不包含 List 遍历、分配、元数据比较、树推理和算术；这些均被实际在线计时，但不是机器成本定理。Lean 到编译器、运行时和机器之间仍是可信边界。
